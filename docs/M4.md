# 0.1.2 共享工具与发布检查

本轮目标已调整为先完成本机开发版：0.1.2 默认工具地址为 `http://127.0.0.1:8080`，服务由开发者另行启动，客户端设置允许改地址；用户仍只填写模型 URL、model、Key，不填写工具凭据。公网部署不是本次发布前提。

## 已完成实现

- 复用现有官方 MCP/API 适配器，新增轻量共享服务和 HTTP 客户端，不新增账号、数据库或框架。工具密钥只在服务端；客户端只发送工具查询参数。
- 服务端具备工具白名单、参数校验、请求体限制、并发/IP/日额度限制及固定错误脱敏。公共状态不包含其他用户最近的调用。
- 打包默认内置本机工具地址，`STA_SHARED_TOOLS_URL` 可覆盖。仅允许无凭据、无查询参数/片段的 HTTPS 或回环 HTTP 地址；本机模式 tag 构建无需访问工具服务。显式 HTTPS 模式仍检查五个服务条目的配置和可用地点查询工具。
- Windows 新增一次性 CI runner 内的真实 updater/NSIS 检查：坏包、中断、安装后版本和二进制哈希、已安装 Python 启动、JSON 与目录配置保留。不会在开发者电脑上运行该安装探针。
- 正式发布使用当前版本的说明文件，四架构全部成功后再发布完整资产。

## 发布顺序

1. 开发者在自己的环境文件中配置四项工具凭据，运行 `npm run tools:dev`；客户端默认使用 `http://127.0.0.1:8080`。
2. 验证本机工具目录、真实只读地点查询与客户端地址设置。以后若使用 HTTPS 服务，可设置构建变量 `STA_SHARED_TOOLS_URL` 或直接修改客户端设置；本次不要求部署公网服务。
3. 对默认本机模式的最终源码运行四架构构建和原生升级检查，记录明确提交与产物。
4. 推送对应 `v0.1.2` 标签，流水线合并全部签名资产并发布；旧客户端的编译地址始终指向 GitHub 正式 latest。
5. 用正式 0.1.1 Windows 客户端检查更新、下载验签并安装重启，核对 0.1.2 与原会话、行程、草稿和数据目录。这一步依赖正式 latest 已发布，不能用发布前探针冒充 GUI 验收。
