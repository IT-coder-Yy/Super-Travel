# 0.1.2 共享工具与发布检查

本轮目标：正式安装包内置共享工具服务地址，用户仍只填写模型 URL、model、Key；补齐 Windows 升级验证后发布 0.1.2。

## 已完成实现

- 复用现有官方 MCP/API 适配器，新增轻量共享服务和 HTTP 客户端，不新增账号、数据库或框架。工具密钥只在服务端；客户端只发送工具查询参数。
- 服务端具备工具白名单、参数校验、请求体限制、并发/IP/日额度限制及固定错误脱敏。公共状态不包含其他用户最近的调用。
- 打包时内置公开 HTTPS 地址。正式 tag 构建要求地址已配置、五个服务条目已配置且至少一个地点查询工具可用，防止发布没有工具入口的安装包。
- Windows 新增一次性 CI runner 内的真实 updater/NSIS 检查：坏包、中断、安装后版本和二进制哈希、已安装 Python 启动、JSON 与目录配置保留。不会在开发者电脑上运行该安装探针。
- 正式发布使用当前版本的说明文件，四架构全部成功后再发布完整资产。

## 当前验证与待完成项

- 源码 `ee03bbf737a1020615dcbe84195d9757a1cfc799` 的[四架构 CI](https://github.com/IT-coder-Yy/SuperTravelAgent/actions/runs/40684418728) 已完整成功，包含产物上传与缓存收尾。Windows x64、macOS Intel/Apple Silicon、Linux x64 各通过后端 217 项、发布检查 19 项（9 项 Node、6 项 Windows 验证守卫、4 项 Release 检查）、Rust 单元测试和真实系统凭据读写删除。逐目标证据见 [M4 原生验证记录](m4-native-validation.json)。
- **Windows 实际结果**：在一次性 CI runner 安装正式 0.1.1，再由原生 Tauri updater 验签并调用 NSIS 安装本轮 0.1.2；坏包及下载中断均被拒绝且旧安装保留。新版 PE 版本、完整主程序/后端哈希、已安装 Python 后端启动与 JSON 读写、会话/行程/草稿/目录配置字节保留全部通过。此项由 CI 原生 API 驱动；**未测试旧客户端 GUI 点击更新及新版桌面重启**，不能替代发布后的 GUI 验收。
- macOS 两架构及 Linux 已通过原生启动/退出清理、0.1.0 → 0.1.2 签名安装、坏包/下载中断拒绝和 JSON 保留；Linux 共享服务镜像构建、健康检查和缺少凭据时拒绝工具调用均通过。
- [实际服务适配器验证](shared-tools-live-validation.json)：新客户端通过进程内 HTTP/ASGI 共享服务调用官方百度地点接口，1 次查询返回 10 个可归一化地点；共发现 26 个只读工具，未调用模型，请求与日志未发现共享凭据。此记录明确不代表公网服务已部署。
- 尚未确定服务的 HTTPS 部署目标；**公网服务未部署，本轮 CI 产物未内置正式共享服务地址，0.1.2 未发布**，没有把本机凭据上传到任何新平台。部署目标确定后，还需验证正式服务的真实只读查询、内置该地址的最终四架构构建与更新，再执行发布后的旧客户端 GUI 验收。

## 发布顺序

1. 在选定服务器部署 [共享工具服务](../deploy/shared-tools/README.md)，只配置四项工具凭据。
2. 验证正式 HTTPS 地址、工具目录及真实只读地点查询，将公开地址设置为仓库变量 `STA_SHARED_TOOLS_URL`。
3. 对最终源码运行四架构构建和原生升级检查，记录明确提交与产物。
4. 推送对应 `v0.1.2` 标签，流水线合并全部签名资产并发布；旧客户端的编译地址始终指向 GitHub 正式 latest。
5. 用正式 0.1.1 Windows 客户端检查更新、下载验签并安装重启，核对 0.1.2 与原会话、行程、草稿和数据目录。这一步依赖正式 latest 已发布，不能用发布前探针冒充 GUI 验收。
