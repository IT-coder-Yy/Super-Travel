# 真实行程闭环（0.1.2 开发版）

本轮沿用 Tauri、React、Python、双 Agent 和现有 JSON 文件。新增一个行程模块和一个真实地图组件，没有引入数据库或新的 Agent 框架。

## 使用流程

1. 在设置中填写模型 URL、model 和 Key；外部服务仍由开发者配置。
2. 新建会话，输入国内单目的地、1～7 天及偏好。缺少必要信息先询问，普通聊天不生成行程。
3. 规划 Agent 写步骤；执行 Agent 查询真实地点，提交结构化日程。首次成功后保存为正式行程，并在地图上显示地点。
4. 通过聊天调整行程，或打开编辑器修改时间、备注、顺序。修改先保存在草稿中；更改地点名称会清除旧坐标，必须重新定位。
5. 点击“应用修改”后替换正式行程，并保留上一版。未定位地点、重叠时段或保存失败都不会覆盖正式版。
6. 刷新、重新启动或从历史打开后恢复本机 JSON。可放弃草稿，也可恢复上一版正式行程。

手动重新定位只接受目的地内唯一、完整同名的地图结果；名称不明确时保留草稿，提示补全地点名称或通过对话补充地址。

## 数据与实现

- `backend/trips.py`：规范化地图结果、结构化行程、地点 ID 与时间校验。模型只能引用已查到或已有行程中的地点 ID，后端填写名称、地址、坐标；明确指定的每日地点数量和地图供应商在提交时再次校验。
- `backend/agents.py`：复用原来的规划、执行、取消、重规划与调用次数限制，增加查询地点和提交行程两种旅行操作。旅行模式不向模型提供原始坐标工具，避免把已归一的坐标混用于其他供应商路线接口。
- `backend/trip_api.py`：应用草稿、重新定位、恢复上一版。普通自动保存不能伪造地图坐标或直接替换正式行程。
- `src/components/RealMap.tsx`：Leaflet 负责真实底图、拖动、缩放、地点标记及选择同步；空行程不请求瓦片，底图失败时保留已定位地点并显示错误。
- 每份会话仍是一个 JSON：`days/trip` 为正式版，`draft/draftTrip` 为待应用修改，`previousTrip` 保留一份可恢复版本。沿用修订冲突检测、备份和原子写入。

## 当前边界

地图展示使用 [Leaflet](https://leafletjs.com/reference.html) 和 [OpenStreetMap 公共瓦片](https://operations.osmfoundation.org/policies/tiles/)，保留来源标注、浏览器缓存和应用身份，只加载当前视图。公共底图没有可用性保证；正式规模化分发前需确认稳定的地图服务。百度、高德坐标经近似转换后用于地图展示，算法来源与 MIT 许可保留在 `trips.py`；不用于精确导航。

本轮不提供道路导航、车次预订、实时票价、营业时间保证或自动预算核算。行程时间与停留为建议，开放与预约仍需出发前确认。用户无需逐个活动填写来源；地点核验信息保存在内部结构中。

正式分发的共享工具凭据保护仍见 [外部服务接入](EXTERNAL_SERVICES.md)。0.1.2 尚未发布 Release；当前正式下载仍为 0.1.1。
