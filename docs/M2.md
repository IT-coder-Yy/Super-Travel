# 双 Agent 接入进展（0.1.2 开发版）

0.1.1 已发布，包含 C2 图标、约 3 秒开场、任意键跳过、JSON 恢复与三平台更新。以下属于下一版开发内容，不能当作完整第一阶段已经验收。

## 已接入

- 规划 Agent 分流普通答复、澄清、计划与进度询问；执行 Agent 按计划调用工具。临时失败最多额外重试一次，重规划最多两轮，每次执行默认最多 12 次工具调用。
- 普通聊天不打断执行；修改任务使旧运行失效。消息立即受理、后台执行、界面轮询进度；刷新不重新发起任务，重启把未完成任务标为已中断。
- 会话、消息、计划与执行进度保存在同一 JSON；取消、切换模型、关闭、恢复损坏文件时，旧结果不能回写。
- 后台保存失败时显示“未完整保存”，保留已有文件与修订号，不能把内存结果冒充已保存结果，也不会一直停留在执行中。
- 针对本机实际出现的 Windows 文件替换访问拒绝，仅对该替换操作最多额外尝试 3 次，总等待 170ms；持续失败仍报告错误，不重复模型/工具请求。
- 模型设置包含地址、模型名和 API Key。桌面版本使用系统凭据库，非秘密配置另存 `model.json`；浏览器开发模式仅在后端内存保存 Key。更换服务地址必须明确填写新 Key，不把旧 Key 发送到新地址。
- 用户只填写模型三项，其余外部服务由开发者统一维护。已改为各家官方 MCP/API 直连并移除本机独立网关；详情见 [外部服务接入](EXTERNAL_SERVICES.md)。

## 本机开发

不再需要本机工具网关。明确指定 `STA_DEV_ENV_FILE` 后运行 `npm run dev`，按[外部服务配置](EXTERNAL_SERVICES.md)读取模型三项及四项工具凭据。模型仍可在设置中填写，工具由开发者维护；任何凭据均不进入浏览器或公开安装包。

界面业务测试使用隔离临时目录、真实 API/JSON 存储与明确标记的假模型/工具；模型与工具的真实联网证据独立记录。仅运行 UI 回归不会消耗真实服务额度。

## Intel macOS 打包注意

本轮 CI 的 `cryptography 50.0.2` 在 Intel macOS 上从源码安装，默认动态链接的 Homebrew OpenSSL 与 Python 自带同名库冲突，冻结包启动时报告缺少 `_SSL_get0_group_name`。流水线改用[官方静态构建方式](https://cryptography.io/en/latest/installation/#building-cryptography-on-macos)，并在冻结前检查动态链接列表；依赖版本不降级。其他平台保持原安装方式。

本地 Intel macOS 构建时，已安装 Homebrew `openssl@3` 后，可使用以下命令安装依赖；避免复用此前构建的动态 wheel：

```sh
OPENSSL_STATIC=1 OPENSSL_DIR="$(brew --prefix openssl@3)" \
  backend/.venv/bin/python -m pip install --no-cache-dir --no-binary cryptography \
  --force-reinstall -r backend/requirements-dev.txt
```
