# 0.1.3：双层 ReAct 与行程可行性

这是第一阶段的收尾开发，尚未创建 0.1.3 Release；当前公开下载仍为 0.1.2。旧项目不作修改，Tauri、React、Python、双 Agent 和本地 JSON 保持不变。

## 本轮实现

- **规划循环**：简单问题直答，信息不足通过对话追问，复杂需求展示计划并自动执行；执行失败反馈后修订剩余计划，成功后由规划 Agent 汇总最终方案。
- **执行循环**：按当前步骤调用允许的本地工具、MCP 或外部 API，检查结果后继续；无法实施时通过 `report_plan_issue` 反馈。保留有限修订、取消和迟到结果隔离。详见[双层 ReAct](DUAL_AGENT.md)。
- **相邻路线**：按步行、驾车或公共交通查询实际路线耗时和距离。模型只传地点 ID；代码使用供应商原坐标，地图展示坐标不进入原始路线接口。缺失或失败明确标为未知。
- **时间校验**：已知交通耗时超过两活动间隔时，阻止生成或应用，并返回可调整的具体冲突。地点、顺序、方式变化使相应证据失效；超过 24 小时重新核查。每段最多等待 12 秒，应用草稿最多核查 30 秒。
- **费用**：编辑草稿时可填写人民币活动费用，以整数分保存。留空为未知，0 为确认免费；页面汇总全部天数的已知费用与未知项数。当前金额由用户确认，不从网页文字推断价格，也不允许模型自行提交金额。
- **兼容与保存**：旧 JSON 缺少新字段仍可打开。草稿、正式版、上一版及修订冲突继续沿用原流程；模型最终汇总失败不会重新调用工具或丢弃已完成的行程。

离线回归使用明确标注的固定模型与地图资料，覆盖双层循环、错误反馈、取消、旧 JSON、路线证据、时间冲突、费用与重启恢复。真实调用另行记录，不以固定资料替代。

- 本机完整后端与原生界面服务夹具 **282 项通过**（后端 278 项、夹具 4 项），此前业务界面 **16 项通过**；单独联网照片检查未运行，前端生产构建通过，发布配置检查 **23 项通过**。
- [真实案例记录](m5-live-validation.json)：杭州 1 天（2 地点/1 路线）、成都 3 天（6 地点/3 路线）、北京 7 天（14 地点/7 路线）均完成真实模型与百度查询、规划汇总、费用草稿应用、JSON 保存和新服务实例读取。
- 成都案例发生一次重规划后成功。北京 7 天首轮模型超时；压缩模型候选地点字段、按 1～2 天分组执行后复验成功，原失败记录仍保留。
- [高德真实算路记录](amap-route-validation.json)：生产工具服务经官方 REST 查询步行路线成功，返回 209 米 / 167 秒，正确取整为 3 分钟，绑定行程并通过 JSON 重读。输入为官方 GCJ-02 样例坐标与明确的验收占位地点 ID；高德实时地点搜索经 MCP、REST 均返回额度不足，完整地点检索到行程链路仍待额度恢复。驾车与公交通过回归，未额外进行真实调用。
- [三平台 CI](https://github.com/IT-coder-Yy/SuperTravelAgent/actions/runs/40704649959) 对源码提交 `14286ac82960dc409b384ca2635dfd662188c498` 的四架构均成功：Windows x64、macOS Intel/Apple Silicon、Linux x64。原生启动、签名更新、坏包/中断拒绝、系统凭据和数据保留的具体证据见[逐平台记录](m5-native-validation.json)。main 构建未发布 Release。

真实验收脚本为 `scripts/verify-trip-scenarios.py`，需要开发者设置 `STA_MODEL_BASE_URL`、`STA_MODEL_NAME`、`STA_MODEL_API_KEY` 和 `STA_SHARED_TOOLS_URL`，再显式传入 `--live`。脚本会消耗真实服务额度，只写入 `.local/live-trip-scenarios-*` 的独立目录，不覆盖原会话；默认验证 1、3、7 天。

## 范围边界

路线耗时是查询当时的估计，不是未来路况保证；地图仍用于地点展示，没有增加道路导航。费用小计不含未填写的交通、住宿等开支。营业窗口、实时票价、预约保证和自动订票不在本轮实现中。

公网工具服务仍按已确认安排留到上线前部署。三平台构建/原生更新记录与完整界面验收分开记录；浏览器回归不能冒充三个系统安装包内的完整交互验收。
